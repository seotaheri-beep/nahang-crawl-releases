# شروع کار با Nahang Crawl

[English](QUICK_START.en.md) · [حریم خصوصی](PRIVACY.fa.md) · [محدودیت‌ها](KNOWN_LIMITATIONS.md) · [گزارش اشکال](SUPPORT.md)

## نصب و اجرای نخست

1. بستهٔ Windows x64 را از [صفحهٔ انتشار رسمی](https://github.com/seotaheri-beep/nahang-crawl-releases/releases) دریافت کنید. برای اجرای برنامه به Node.js، Java یا ابزار توسعهٔ سراسری نیاز نیست.
2. اگر بستهٔ Setup ارائه شده، آن را اجرا کنید. برای بستهٔ ZIP، همهٔ محتوا را در پوشه‌ای تازه استخراج و `NahangCrawl.exe` را از همان پوشه اجرا کنید؛ EXE را به‌تنهایی از فایل‌های کناری جدا نکنید.
3. بسته‌های فعلی بتا و بدون امضای دیجیتال‌اند. منبع و SHA-256 فایل را با اطلاعات همان انتشار تطبیق دهید. این راهنما توصیه به خاموش‌کردن حفاظت Windows نمی‌کند.
4. نصب‌کنندهٔ قابل دریافت در یک انتشار ممکن است با نامزد آزمایشی توسعه متفاوت باشد. نسخهٔ پایین پنجره را با یادداشت همان انتشار تطبیق دهید.

این برنامه یک نسخهٔ واحد دارد؛ فعال‌سازی لایسنس و جداسازی رایگان/پولی در نسخهٔ فعلی وجود ندارد. برای اولین خزش، اتصال Google یا کلید API لازم نیست. راهنمای آفلاین با **F1** باز می‌شود.

## اولین خزش

1. در نوار آدرس، نشانی دقیق مانند `https://example.com/` را وارد کنید. سایتی را انتخاب کنید که اجازهٔ بررسی آن را دارید.
2. حالت **Spider** را نگه دارید. محدودهٔ **Subdomain** به میزبان شروع مربوط است؛ Domain و Subfolder دامنهٔ بررسی را تغییر می‌دهند. برای شروع سقف **۵۰۰ URL**، دو درخواست هم‌زمان و فاصلهٔ پیش‌فرض را نگه دارید.
3. **شروع کاوش** را بزنید. برای مکث F7، ادامه F9 و توقف F8 در دسترس‌اند. نتایج هنگام دریافت اضافه می‌شوند.
4. در تب داخلی، یک ردیف را انتخاب کنید. جزئیات URL، لینک‌ها و شواهد ذخیره‌شده در پنل پایین‌اند. با Tab به جدول بروید؛ Enter ردیف را انتخاب و کلیدهای بالا/پایین بین ردیف‌ها حرکت می‌کنند.
5. اگر سقف URL پر شد، بخشی از سایت بررسی نشده است. محدودیت را از تنظیمات خزش برای اجرای تازه تغییر دهید. ادامهٔ خزش از تنظیمات ذخیره‌شدهٔ خودش استفاده می‌کند.

برای سایت وابسته به JavaScript، پیش از اجرای تازه از **تنظیمات ← Crawl Config ← Spider ← Rendering** رندر JavaScript را فعال کنید. مرورگر داخلی باید روشن باشد. رندر منابع بیشتری مصرف می‌کند و کامل‌بودن lazy-load یا تعامل‌های سایت تضمین نمی‌شود.

## گزارش و خروجی

- تب، فیلتر، جست‌وجو و Segment بر نمای فعلی اثر دارند. جدول خالی همیشه به معنی نبود داده نیست؛ این انتخاب‌ها را بررسی کنید.
- **خروجی CSV** برای بررسی در Excel است. **خروجی‌ها ← Multi-Export** چند گزارش و فایل را یک‌جا ذخیره می‌کند.
- **گزارش‌ها** خلاصه‌ها و بررسی‌های تخصصی را دارد. برای تحلیل‌های پس از خزش، اجرای جاری را مکث یا کامل کنید و **کاوش و تحلیل ← Start** را بزنید.
- گزارش از شواهد ذخیره‌شده ساخته می‌شود. نبود دادهٔ PageSpeed، رندر، هدر یا دسترس‌پذیری به معنی سالم‌بودن آن بخش نیست.
- noindex، canonical و alt خالی ممکن است عمدی باشند. نتیجهٔ ابزار را با هدف صفحه تفسیر کنید.

## ذخیره، بازگشایی و پشتیبان

| نیاز | مسیر |
|---|---|
| بازکردن اجرای قبلی | فایل ← خزش‌ها، یا Ctrl+O |
| فایل قابل بازگشایی/انتقال | فایل ← خروجی ← فایل خزش، یا Ctrl+Shift+S؛ پسوند `.nahang-crawl` |
| واردکردن فایل خزش | فایل ← Import، یا Ctrl+Shift+O |
| نسخهٔ پشتیبان | فایل ← پشتیبان‌گیری و انتقال |
| نمای خزش تازه | فایل ← New یا Ctrl+N؛ اجرای قبلی در تاریخچه باقی می‌ماند |

در **Database** تغییرات هنگام کار ثبت می‌شوند. در **RAM** پیش از خروج **Ctrl+S** بزنید؛ CSV جای ذخیرهٔ جلسه یا پشتیبان را نمی‌گیرد. داده‌های برنامه معمولاً در `%APPDATA%\NahangCrawl` قرار دارند؛ مسیر فعال پایگاه داده را در تنظیمات برنامه ← Storage Mode ببینید. تغییر پوشهٔ Database فایل‌های قبلی را خودکار جابه‌جا یا ادغام نمی‌کند. نگهداری خودکار خزش‌ها به‌صورت پیش‌فرض Never است؛ تغییر آن می‌تواند اجرای قدیمیِ مشمول سیاست را حذف کند.

پیش از ارتقا، از داده‌ها پشتیبان بگیرید و عملیات فعال را تمام کنید. ZIP نسخهٔ جدید را در پوشه‌ای جدا استخراج کنید. پوشهٔ دادهٔ کاربر را حذف نکنید. از **راهنما ← Check for Updates** نسخهٔ منتشرشده را بررسی کنید؛ Auto Check اختیاری و پیش‌فرض خاموش است. دریافت و اجرای فایل نصب با اقدام شما انجام می‌شود.

## تنظیمات و رفع مشکل

زبان فارسی/انگلیسی، پوسته، رنگ تأکیدی و Focus Mode در **فایل ← Settings** هستند. تنظیمات برنامه از تنظیمات یک خزش جداست. تغییر Storage، Memory و بعضی گزینه‌های شبکه/مرورگر به شروع بعدی برنامه نیاز دارد؛ پیام همان بخش را بخوانید.

اگر فقط یک URL دیده می‌شود، کد پاسخ و ریدایرکت را بررسی کنید؛ Proxy، robots.txt، محدوده، Include/Exclude و سقف خزش می‌توانند علت باشند. صفحهٔ ورود یا چالش امنیتی هم ممکن است به‌جای محتوای سایت برگردد. تنظیمات شبکهٔ سیستم را بدون بررسی تغییر ندهید.

اگر گزارش API خالی است، بازهٔ زمانی، Property و وجود داده را بررسی کنید. اتصال موفق GA4 با دادهٔ غیرصفر یکسان نیست. خطای quota مربوط به سهمیهٔ ارائه‌دهنده است. برای Ollama، سرور و مدل محلی مناسب باید جداگانه آماده باشند؛ برنامه مدل را خودکار دانلود نمی‌کند.

برای گزارش خطا، نسخه و مراحل بازتولید را ثبت و **راهنما ← Debug ← Save Logs** را انتخاب کنید. [راهنمای گزارش اشکال](SUPPORT.md) توضیح می‌دهد چه داده‌ای را می‌توان در گزارش عمومی قرار داد.
